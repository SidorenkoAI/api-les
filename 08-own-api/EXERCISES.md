# Урок 8. Задания

Ниже — подсказки, **не готовый код**. Эталонные решения — в папке [solutions](solutions/README.md).

Задания бывают двух видов:

- **сервер** — дорабатываешь свой зоопарк. Скопируй `main.py` в новый файл (например,
  `zoo_random.py`) и добавляй туда. Проверяй в браузере и в `/docs`, а лучше — попроси соседа
  сходить к тебе своим клиентом;
- **клиент** — программа на `requests`, которая ходит в зоопарк соседа (или в твой, если
  сосед занят): `BASE_URL = "http://<IP соседа>:8000"`.

Не забывай: **после правки сервера — перезапуск** (Stop → Run). И только один сервер на порт 8000
за раз.

  Как FastAPI понимает, что «random» — это не номер зверя?

### 2. Статистика зоопарка (сервер)

Добавь `GET /stats`: сколько всего зверей, средний возраст, самый старый зверь, сколько ног во
всём зоопарке, сколько зверей с каждой планеты.

```json
{
  "total": 6,
  "average_age": 11.5,
  "oldest": {"id": 3, "name": "Топотун", "age": 40},
  "legs_total": 20,
  "by_planet": {"Мурлыка": 1, "Аквамарина": 1, "...": 1}

```

- Это задачи урока 1, только ответ уходит не в `print`, а в `return`.
- Словарь «планета → сколько» — счётчик через `.get(ключ, 0) + 1`.
- Самый старый — `max(animals, key=...)`.
- Добавь зверя через `/docs` — изменилась ли статистика? Почему не пришлось ничего пересчитывать
  вручную?

### 3. Перепись соседского зоопарка (клиент)

Программа запрашивает у соседа всех зверей и печатает: таблицу (номер, имя, вид, планета,
возраст), отсортированную по возрасту; список имён по планетам; самого старого зверя; сколько
всего ног в зоопарке.

- Всё нужное приходит одним запросом: `/animals`.
- Ровная таблица — f-строки с шириной: `f"{name:<10}"` (влево), `f"{age:>4}"` (вправо).
- Словарь «планета → список имён»: `.setdefault(планета, []).append(имя)`.
- Если сосед не запустил сервер — программа не должна падать (урок 4: `try`/`except
  requests.RequestException`).

## Средние

### 4. Поиск и сортировка (сервер)

Научи `GET /animals` новым параметрам: `name` — часть имени без учёта регистра (`?name=пу`
найдёт Пушка), `sort` — по какому полю сортировать (`id`, `name`, `age`, `legs`), `order` —
`asc` или `desc`. Неверный `sort` или `order` — ошибка **400** с объяснением, какие значения
допустимы.

- Новые параметры — просто новые аргументы функции со значениями по умолчанию:
  `sort: str = "id"`.
- «Часть имени»: оператор `in` для строк — `"пу" in "пушок"`.
- Сортировка по полю, имя которого лежит в переменной: `key=lambda animal: animal[sort]`.
- Ошибка 400 — тот же `HTTPException`, что для 404, только другой код.
- Сравни свой ответ с ответом Космопорта на `/planets?sort=color` (урок 4). Похоже?

### 5. Удалить зверя и день рождения (сервер)

Добавь два адреса:

- `DELETE /animals/{animal_id}` — удалить зверя, ответ `{"message": "Шуршик покинул зоопарк",
  "left": 5}`. Нет такого — 404.
- `POST /animals/{animal_id}/birthday` — возраст зверя +1, ответ с поздравлением и обновлённым
  зверем. Тела у этого запроса нет.

- Маршрут для удаления — `@app.delete(...)`. Проверить можно в `/docs` или
  `requests.delete(url)`.
- Поиск «зверь или 404» теперь нужен в трёх местах — вынеси его в отдельную функцию `find`.
- `список.remove(элемент)` удаляет элемент из списка.
- Удали зверя №6 и добавь нового. Какой у него номер? Почему опасно выдать ему снова №6? Как
  сделать, чтобы номера никогда не повторялись? (Подсказка: переменная-счётчик и `global`.)

### 6. Посылка соседу (клиент)

Отправь в зоопарк соседа «посылку» — 5 зверей, среди которых есть неправильные: возраст словом
(`"старый"`), зверь без планеты, возраст строкой-числом (`"4"`). Для каждого напечатай, что
ответил сервер: принят (и какой номер дали) или нет (и почему). В конце — сколько принято и
сколько зверей теперь у соседа.

```
нормальный: 201 — принят под номером 7
возраст словом: 422 — age: Input should be a valid integer, unable to parse string as an integer
без планеты: 422 — planet: Field required
```

- Посылка — список пар `(название, словарь)`, и цикл по нему.
- Разбор ошибки — функция `explain` из `client.py`. Чем `detail` у 404 отличается от `detail`
  у 422?
- Какой зверь прошёл, хотя ты ждал ошибку? Почему FastAPI его принял?

### 7. Ключ API у своего зоопарка (сервер)

Теперь ты — Космопорт из урока 6. Смотреть зверей может кто угодно, а **добавлять** — только
с заголовком `X-API-Key`. Ключи раздаёшь ты: словарь `KEYS = {"zoo-vasya-42": "Вася", ...}`.
Без заголовка — **401**, с неизвестным ключом — **403**. У нового зверя появляется поле
`added_by` — имя того, кто его привёз. Добавь `GET /me`, как у Космопорта.

- Заголовок в аргументах функции: `from fastapi import Header`, затем
  `x_api_key: str | None = Header(default=None)`. FastAPI сам найдёт заголовок `X-API-Key`:
  дефисы в имени заголовка превращаются в подчёркивания.
- Проверка ключа нужна в двух маршрутах — отдельная функция, которая возвращает имя или
  делает `raise HTTPException(...)`.
- Выдай ключ соседу (только ему!) и попроси добавить зверя из клиента с `headers=`.
- Пришли **без ключа** зверя с неправильным телом. Какой код пришёл: 401 или 422? Почему?

## Посложнее

### 8. Зоопарк в файле (сервер)

Сейчас после перезапуска сервера новые звери пропадают. Сделай, чтобы зоопарк хранился в файле
`zoo.json`: при запуске сервер читает его, а после каждого нового зверя — сохраняет.

- Это урок 2: `json.load` и `json.dump`, `encoding="utf-8"`, `ensure_ascii=False`, `indent=2`.
- Файла при первом запуске ещё нет — `FileNotFoundError`. Тогда начинаем со стартовых зверей.
- Проверь: добавь зверя → Stop → Run → зверь на месте? Открой `zoo.json` в PyCharm.
- Если делал задание 5 — сохраняй и после удаления, и после дня рождения.

### 9. Мост в Космопорт (сервер)

Добавь `GET /animals/{animal_id}/home`: зверь и сведения о его родной планете — тип,
гравитация, температура, есть ли вода. Сведения о планете твой сервер берёт **у Космопорта**
(`/planets/<имя>`) через `requests`. Получится сервер, который сам является клиентом другого
сервера.

```json
{
  "animal": {"id": 1, "name": "Пушок", "...": "..."},
  "home": {"name": "Мурлыка", "type": "ocean", "gravity": 0.8, "temperature": {"min": 12, "max": 32}, "has_water": true},
  "message": "Пушок родом с планеты Мурлыка: гравитация 0.8 g, от 12 до 32 °C"
}
```

- Внутри функции маршрута — обычный `requests.get(BASE_URL + "/planets/" + ...)`, как на уроке 3.
  `BASE_URL` — адрес Космопорта.
- Зверь с выдуманной планеты (добавь зверя с `"planet": "Плутон"`) — Космопорт ответит 404.
  Что должен ответить **твой** сервер?
- Космопорт не отвечает (выключи интернет или испорть `BASE_URL`) — ответь кодом **502**
  («тот, у кого я спрашиваю, не отвечает»). Не забудь `timeout=`!
- Придумай ещё: `/animals/{id}/weather` — погода на родной планете зверя сегодня (урок 5).
