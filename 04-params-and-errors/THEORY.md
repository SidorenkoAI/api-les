# Урок 4. Параметры запроса и ошибки — теория и разбор кода

На уроке 3 мы просили у сервера то, что лежит по адресу: список планет, одну планету. Сегодня
научимся **уточнять** запрос: «дай пять случайных инопланетян, и пусть они будут одинаковыми у
всего класса». А ещё сделаем так, чтобы программа не падала, если интернет пропал или сервер
задумался.

## Подробный разбор: строка запроса

Открой в браузере два адреса:

```
https://api-lessons-sidorenkoai.msk1.amvera.tech/planets
https://api-lessons-sidorenkoai.msk1.amvera.tech/planets?type=ocean&full=true
```

Во втором после пути стоит `?`, а за ним — **параметры запроса**:

```
/planets?type=ocean&full=true
        └───┬────┘ └───┬───┘
        параметр 1  параметр 2   (между ними — &)
```

Каждый параметр — пара `имя=значение`. Это как аргументы функции, только для сервера. Какие
параметры понимает сервер, написано в его документации: `/docs`.

Параметры можно дописать в адрес руками, но в Python так не делают. `requests` соберёт строку
запроса сам из словаря:

```python
params = {"type": "ocean", "full": "true"}
response = requests.get(BASE_URL + "/planets", params=params)
print(response.url)   # .../planets?type=ocean&full=true
```

`response.url` — адрес, по которому на самом деле ушёл запрос. Если что-то работает не так, первым
делом печатай его.

Если в значении русские буквы или пробелы, `requests` их «закодирует»: `Мурлыка` в адресе станет
`%D0%9C%D1%83...`. Так и должно быть: в адресах можно использовать только латиницу, а остальное
записывается кодами. Сервер раскодирует обратно сам.

## Подробный разбор: что такое seed

Адрес `/aliens/random?count=3` каждый раз даёт новых инопланетян. Но если добавить `seed=42`, ответ
будет **одинаковым** — сколько раз ни спрашивай и у кого угодно в классе.

Компьютер не умеет выдумывать по-настоящему случайные числа. Он берёт начальное число —
**зерно** (*seed*) — и по формуле получает из него длинную цепочку чисел, которые выглядят
случайными. Одинаковое зерно — одинаковая цепочка. Так устроена генерация мира в играх: введи тот
же seed — получишь тот же мир.

## Разбор кода урока

### Шаг 1. Собираем параметры

```python
CREW_SIZE = 5
TIMEOUT = 10

seed = input("Номер экипажа (целое число, Enter — случайный экипаж): ").strip()

params = {"count": CREW_SIZE}
if seed:
    params["seed"] = seed
```

`params` — обычный словарь. Если пользователь ничего не ввёл, параметра `seed` в запросе не будет,
и сервер выберет случайных инопланетян. Если ввёл — добавляем в словарь ещё один ключ.

### Шаг 2. Запрос с параметрами и таймаутом

```python
response = requests.get(BASE_URL + "/aliens/random", params=params, timeout=TIMEOUT)
print("Адрес запроса:", response.url)
```

`timeout=10` — «жди ответа не больше 10 секунд». Без него программа может висеть очень долго, если
сервер не отвечает. **Всегда указывай `timeout`** в настоящих программах.

### Шаг 3. Ошибка 400: сервер не понял запрос

```python
if response.status_code == 400:
    error = response.json()
    print("Сервер не понял запрос:", error["error"])
    for detail in error["details"]:
        print(f'  {detail["param"]}: {detail["message"]}')
```

Если ввести seed `abc`, сервер ответит кодом **400** (*Bad Request* — «неверный запрос») и объяснит,
что именно не так:

```json
{
  "error": "Неверные параметры запроса",
  "details": [
    {"param": "seed", "message": "должно быть целым числом"}
  ]
}
```

Ошибок может быть несколько сразу, поэтому `details` — список. Проходим по нему циклом.

### Шаг 4. `raise_for_status()` — все остальные ошибки одной строкой

```python
else:
    response.raise_for_status()
    crew = response.json()["results"]
```

Писать `if` на каждый возможный код ответа долго. `raise_for_status()` проверяет код сам:

- код **2xx** (успех) — ничего не делает, программа идёт дальше;
- код **4xx** или **5xx** — выбрасывает исключение `requests.HTTPError`.

### Шаг 5. Экипаж и капитан

```python
captain = crew[0]
for alien in crew:
    if alien["age"] > captain["age"]:
        captain = alien
```

Поиск максимума — как на уроке 1: «пусть капитан — первый, а если встретим кого-то старше — он
капитан». Навыки команды собираем в список без повторов: добавляем навык, только если его там ещё
нет (`if skill not in team_skills`).

### Шаг 6. Скачиваем картинку: `response.content`

```python
photo = requests.get(captain["photo"], timeout=TIMEOUT)
photo.raise_for_status()
with open("captain.svg", "wb") as file:
    file.write(photo.content)
```

В карточке инопланетянина есть ссылка на портрет. Портрет — это **не JSON**, а картинка, и
`.json()` тут не сработает. У ответа есть три способа посмотреть содержимое:

| Что | Тип | Когда нужно |
|---|---|---|
| `response.json()` | словари и списки | ответ — JSON |
| `response.text` | строка `str` | ответ — текст |
| `response.content` | байты `bytes` | ответ — что угодно: картинка, звук, архив |

Байты пишем в файл, открытый в режиме `"wb"` (*write binary* — «записать байты»). Открой
`captain.svg` в браузере — увидишь капитана. Цвет и число глаз совпадают с его данными.

### Шаг 7. `try`/`except`: когда ответа нет вообще

```python
try:
    response = requests.get(..., timeout=TIMEOUT)
    ...
except requests.RequestException as error:
    print("Не получилось поговорить с сервером:", error)
```

Ошибки 400 и 404 — это **ответ** сервера: он есть, просто с плохим кодом. А бывает, что ответа
нет совсем. Тогда `requests.get` не возвращает ответ, а **выбрасывает исключение**, и если его не
поймать, программа упадёт с длинным красным текстом.

## Подробный разбор: какие бывают исключения

| Исключение | Когда |
|---|---|
| `requests.ConnectionError` | нет интернета, опечатка в адресе, сервер выключен |
| `requests.Timeout` | сервер не ответил за `timeout` секунд |
| `requests.HTTPError` | `raise_for_status()` увидел код 4xx или 5xx |
| `requests.RequestException` | **любая** из ошибок выше — их общий «родитель» |

Можно ловить каждую по отдельности и писать разные сообщения:

```python
try:
    response = requests.get(url, timeout=5)
    response.raise_for_status()
except requests.Timeout:
    print("Сервер не ответил вовремя")
except requests.ConnectionError:
    print("Нет связи с сервером")
except requests.HTTPError as error:
    print("Сервер ответил ошибкой", error.response.status_code)
```

А можно одним `except requests.RequestException` поймать всё сразу.

Попробовать таймаут легко: на нашем сервере есть «медленный» адрес `/slow?seconds=3` — он
нарочно отвечает через 3 секунды. Спроси его с `timeout=1` — получишь `Timeout`.

## Ошибки, которые встречаются чаще всего

| Сообщение | Что случилось |
|---|---|
| `TypeError: can only concatenate str (not "dict") to str` | Приклеиваешь словарь к адресу через `+`. Передай его отдельно: `params=params` |
| Фильтр не работает, а ошибки нет | Опечатка в имени параметра: незнакомые параметры сервер пропускает. Смотри `response.url` |
| `KeyError: 'results'` | Пришла ошибка 400 или 404, а код ответа не проверили |
| `requests.exceptions.ReadTimeout` | Сервер не ответил за `timeout` секунд |
| `requests.exceptions.HTTPError: 404 Client Error` | Это сработал `raise_for_status()` |
| `TypeError: write() argument must be str, not bytes` | Пишешь байты в файл, открытый как `"w"` — нужен `"wb"` |

## Что запомнить

- Параметры запроса — после `?` в адресе: `имя=значение`, между ними `&`.
- В Python параметры передаём словарём: `requests.get(url, params={...})`. Проверка — `response.url`.
- Одинаковый `seed` — одинаковый «случайный» ответ.
- Код **400** — неверный параметр, сервер объясняет в `details`.
- `raise_for_status()` превращает плохой код ответа в исключение.
- Всегда ставь `timeout=` и лови `requests.RequestException` через `try`/`except`.
- Картинки и другие не-текстовые файлы — через `response.content` и `open(..., "wb")`.
