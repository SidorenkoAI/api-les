# Урок 2. JSON — теория и разбор кода

На прошлом уроке планеты лежали прямо в коде Python, в файле `planets_data.py`. Сегодня те же
данные переезжают в файл `planets.json`, а наш справочник научится его читать и сохранять в
JSON свои результаты.

## Зачем нужен JSON

Представь: сервер погоды написан на Java, приложение в телефоне — на Kotlin, сайт — на JavaScript,
а твоя программа — на Python. Всем им нужно обмениваться данными. Код Python они читать не умеют.
Нужен **общий язык данных**, понятный любой программе. Самый популярный такой язык — **JSON**.

JSON почти всегда используют:
- веб-сервисы (погода, карты, игры) — для ответов на запросы, с этим мы будем работать дальше;
- программы — для настроек;
- игры — для сохранений.

## Подробный разбор: как выглядит JSON

Вот планета в JSON (из файла `planets.json`):

```json
{
  "id": 5,
  "name": "Аквамарина",
  "gravity": 1.1,
  "moons": [],
  "temperature": {"min": 5, "max": 28},
  "has_water": true,
  "rings": null
}
```

Очень похоже на словарь Python, правда? Так и задумано. В JSON есть:

| JSON | Пример | В Python становится |
|---|---|---|
| объект | `{"min": 5, "max": 28}` | словарь `dict` |
| массив | `["Тик", "Так"]` | список `list` |
| строка | `"Аквамарина"` | `str` |
| число | `1.1`, `5` | `float`, `int` |
| `true` / `false` | `true` | `True` / `False` |
| `null` | `null` | `None` |

И строгие правила, которые в Python мягче:

- строки и ключи — **только в двойных кавычках** `"..."`; одинарные `'...'` — ошибка;
- ключи объекта — **только строки**;
- **нет запятой** после последнего элемента: `["Тик", "Так",]` — ошибка;
- **нет комментариев**;
- `true`, `false`, `null` — с маленькой буквы.

Главное, что нужно запомнить: **JSON — это текст.** Это одна строка (или файл с текстом), а не
словарь. Чтобы взять у JSON значение по ключу или пройтись по нему циклом, его сначала нужно
**разобрать** в словари и списки Python.

## Подробный разбор: четыре функции модуля `json`

```
                 dumps →                    dump →
данные Python  ─────────►  строка JSON  ────────►  файл
               ◄─────────               ◄────────
                 loads ←                    load ←
```

- `json.dumps(данные)` — данные → строка (*dump string* — «выгрузить в строку»);
- `json.loads(строка)` — строка → данные (*load string* — «загрузить из строки»);
- `json.dump(данные, файл)` — данные → сразу в файл;
- `json.load(файл)` — из файла → данные.

Запомнить легко: **s** на конце — значит работаем со **s**tring, со строкой.

## Разбор кода урока

### Шаг 1. Данные → строка → данные

```python
import json

planet = {"name": "Комета-Х", "moons": [], "has_water": False, "rings": None}

text = json.dumps(planet, ensure_ascii=False)
print(text)        # {"name": "Комета-Х", "moons": [], "has_water": false, "rings": null}
print(type(text))  # <class 'str'>
```

Посмотри внимательно на вывод: `False` превратилось в `false`, `None` — в `null`, кавычки стали
двойными. Это уже не словарь, а строка в формате JSON.

`ensure_ascii=False` — «не превращай русские буквы в коды». Без этого параметра вместо
`Комета-Х` будет `Комета-Х`. Это тоже правильный JSON, и
программы его поймут, но человеку его не прочитать.

```python
again = json.loads(text)
print(type(again))       # <class 'dict'>
print(again == planet)   # True
```

`loads` разбирает строку обратно в словарь. Получился словарь, равный исходному.

### Шаг 2. Читаем файл

```python
with open("planets.json", encoding="utf-8") as file:
    planets = json.load(file)
```

- `open(..., encoding="utf-8")` открывает файл для чтения. `utf-8` — кодировка, в которой записаны
  русские буквы. Без неё Windows может прочитать файл неправильно.
- `with ... as file:` — «открой файл, поработай с ним и закрой сам, когда блок кончится».
- `json.load(file)` читает весь текст из файла и разбирает его.

После этого `planets` — **обычный список словарей**, точно такой же, как на уроке 1. Поэтому
дальше работает весь старый код: циклы, `sorted`, поиск максимума. Программе всё равно, откуда
пришли данные: из `.py`, из `.json` или, как будет на следующем уроке, из интернета.

### Шаг 3. Собираем отчёт

```python
report = {
    "planets_total": len(planets),
    "moons_total": moons_total,
    "with_water": with_water,
    "heaviest": {"name": heaviest["name"], "gravity": heaviest["gravity"]},
    "top_population": top_population,
}
```

Отчёт — тоже словарь. Внутри него число, список строк, словарь и список словарей. JSON всё это
умеет хранить.

### Шаг 4. Сохраняем в файл

```python
with open("report.json", "w", encoding="utf-8") as file:
    json.dump(report, file, ensure_ascii=False, indent=2)
```

- `"w"` — открыть файл **для записи** (*write*). Если файла нет, он создастся. Если есть, то
  **перезапишется целиком**.
- `indent=2` — «красиво, с отступом в 2 пробела». Без него весь JSON будет в одну длинную строку.
  Программам всё равно, а человеку читать удобнее с отступами.

## Подробный разбор: ошибки при чтении JSON

Если в файле ошибка формата, `json.load` падает с `JSONDecodeError`:

```
json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 2 column 3 (char 4)
```

Читаем сообщение:
- *Expecting property name enclosed in double quotes* — «ожидалось имя ключа в двойных кавычках»;
- *line 2 column 3* — ошибка **в строке 2, в столбце 3**. Открываем файл и смотрим туда.

JSON разбирается до **первой** ошибки. Исправил одну, запустил снова, и Python покажет следующую.

Такую ошибку можно «поймать» и показать понятное сообщение вместо падения программы:

```python
try:
    with open("broken.json", encoding="utf-8") as file:
        data = json.load(file)
except json.JSONDecodeError as error:
    print(f"Файл испорчен: строка {error.lineno}, столбец {error.colno}")
```

## Подробный разбор: сюрпризы при переводе в JSON

```python
json.dumps((1, 2))             # '[1, 2]'        — кортеж стал списком
json.dumps({1: "один"})        # '{"1": "один"}' — ключ-число стал строкой!
json.dumps({1, 2})             # ошибка: множество (set) в JSON не сохранить
```

Поэтому после «туда и обратно» данные не всегда совпадают с исходными. Если ключи — числа, после
`loads` их придётся искать как строки: `data["1"]`, а не `data[1]`.

## Ошибки, которые встречаются чаще всего

| Сообщение | Что случилось |
|---|---|
| `FileNotFoundError` | Файла нет в папке, из которой запущена программа (или он называется `planets.json.txt`) |
| `JSONDecodeError` | В JSON ошибка формата — смотри номер строки и столбца |
| `TypeError: the JSON object must be str ... not TextIOWrapper` | Передали файл в `loads` — нужен `load` |
| `AttributeError: 'str' object has no attribute 'read'` | Наоборот: передали строку в `load` — нужен `loads` |
| `TypeError: string indices must be integers` | JSON не разобран: в переменной строка, а не словарь |
| `TypeError: Object of type set is not JSON serializable` | Пытаемся сохранить то, чего нет в JSON |

## Что запомнить

- JSON — текстовый формат данных, понятный любой программе. Похож на словари и списки Python.
- `true`/`false`/`null`, только двойные кавычки, без лишних запятых и комментариев.
- `loads`/`dumps` — для строк, `load`/`dump` — для файлов.
- Всегда `encoding="utf-8"` при открытии файла и `ensure_ascii=False` при записи русского текста.
- После `load` у тебя обычные списки и словари: работай с ними, как на уроке 1.
