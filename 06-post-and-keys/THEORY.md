# Урок 6. POST и ключ API — теория и разбор кода

До сих пор мы только **спрашивали** сервер: «дай список планет», «дай прогноз». Сегодня мы
будем **отправлять** ему свои данные: зарегистрируемся, получим личный ключ и напишем сообщение
на доску станции, которую видит весь класс.

## GET и POST

У каждого HTTP-запроса есть **метод** — что мы хотим сделать.

- **GET** — «дай». Всё, что нужно серверу, помещается в адрес: `/planets/2`,
  `/weather?planet=2&days=3`. Так браузер открывает любую страницу.
- **POST** — «прими». У запроса появляется **тело** — данные, которые мы отправляем. Так
  отправляются сообщения в чатах, анкеты, заказы в интернет-магазине.

Похоже на почту: GET — открытка, где всё написано прямо на адресе. POST — конверт: на нём адрес,
а внутри письмо.

## Тело запроса и `json=`

Тело — это обычно JSON. Помнишь урок 2? JSON — текстовая запись словарей и списков. `requests`
сам превратит словарь в JSON, если передать его через `json=`:

```python
response = requests.post(BASE_URL + "/register", json={"name": "Вася"}, timeout=10)
```

Внутри запроса это выглядит так:

```
POST /register HTTP/1.1
Host: api-lessons-sidorenkoai.msk1.amvera.tech
Content-Type: application/json

{"name": "Вася"}
```

Первая строка — метод и путь, дальше **заголовки**, пустая строка и **тело**.

## Заголовки

**Заголовки** — служебные строки запроса, «надписи на конверте»: в каком формате данные, кто
отправляет, на каком языке ответить. `Content-Type: application/json` `requests` добавил сам,
потому что мы написали `json=`. Свои заголовки передаются словарём `headers=`:

```python
headers = {"X-API-Key": "kp-1a2b3c4d5e6f7a8b"}
response = requests.get(BASE_URL + "/me", headers=headers, timeout=10)
```

У ответа тоже есть заголовки — их мы смотрели на уроке 4: `response.headers["content-type"]`.

## Ключ API

Читать доску может кто угодно. А писать — только тот, кто **представился**. Для этого у каждого
есть **личный ключ API** — длинная случайная строка вроде `kp-1a2b3c4d5e6f7a8b`. По ключу сервер
знает, кто прислал запрос, подписывает сообщения твоим именем и следит, чтобы никто не писал
слишком часто.

Ключ — как пропуск или пароль:

- **не показывай** его соседу и не публикуй — с твоим ключом кто угодно сможет писать от твоего
  имени;
- **не вписывай** ключ прямо в код — код часто показывают другим. Ключ хранят отдельно: в файле
  рядом с программой или в переменной окружения (задание 5).

У настоящих сервисов (погода, карты, нейросети) за запросы часто платят, и ключ привязан к оплате.
Утёкший ключ — это чужие запросы за твои деньги.

## Новые коды ответа

| Код | Название | Что значит | Когда у нас |
|---|---|---|---|
| 200 | OK | всё хорошо | чтение доски, `/me` |
| 201 | Created | создано что-то новое | регистрация, новое сообщение |
| 400 | Bad Request | неверные данные | пустое сообщение, имя из одной буквы |
| 401 | Unauthorized | ты не представился | нет заголовка `X-API-Key` |
| 403 | Forbidden | представился, но не пускаем | ключ неверный |
| 409 | Conflict | конфликт с тем, что уже есть | имя уже занято |
| 429 | Too Many Requests | слишком часто | два сообщения быстрее чем за 3 секунды |

Все коды 4xx значат «ошибка с твоей стороны»: в ответе всегда есть ключ `"error"` с объяснением
по-русски. Если ошибка в данных — ещё и список `"details"`: какое поле и что с ним не так.

## Разбор кода урока

### Шаг 1. Регистрация

```python
def register():
    """Спрашивать имя, пока сервер не выдаст ключ. Вернуть ключ."""
    while True:
        name = input("Как тебя зовут (2–20 символов)? ").strip()
        response = requests.post(BASE_URL + "/register", json={"name": name}, timeout=10)
        if response.status_code == 201:
            data = response.json()
            print(data["message"])
            return data["api_key"]
        print(f"Не получилось (код {response.status_code}):", explain(response))
```

`requests.post` устроен как `requests.get`, только данные идут не в `params=`, а в `json=`.
Сервер отвечает кодом **201** и JSON с ключом:

```json
{
  "name": "Вася",
  "api_key": "kp-1a2b3c4d5e6f7a8b",
  "message": "Привет, Вася! Это твой личный ключ. ..."
}
```

Если имя не подошло — код 400 (слишком короткое, странные символы) или 409 (занято), и цикл
спрашивает снова. `return` внутри `while True` сразу выходит и из цикла, и из функции.

Функция `explain` собирает текст ошибки вместе с подробностями:

```python
def explain(response):
    data = response.json()
    text = data["error"]
    for detail in data.get("details", []):
        text += f" ({detail['param']}: {detail['message']})"
    return text
```

`data.get("details", [])` — если подробностей нет, вернётся пустой список, и цикл просто
не выполнится ни разу (шаблон `.get` с запасным значением из урока 1).

### Шаг 2. Ключ — в файл

```python
def load_key():
    try:
        with open(KEY_FILE, encoding="utf-8") as file:
            return file.read().strip()
    except FileNotFoundError:
        key = register()
        with open(KEY_FILE, "w", encoding="utf-8") as file:
            file.write(key)
        print(f"Ключ сохранён в файл {KEY_FILE}. Не показывай его никому!")
        return key
```

Регистрироваться при каждом запуске нельзя — имя уже занято. Поэтому ключ сохраняем в файл
`key.txt`. При следующем запуске файл уже есть — читаем ключ из него. Если файла нет,
`open` бросит `FileNotFoundError` — значит, это первый запуск, регистрируемся.

`.strip()` убирает пробелы и перенос строки по краям: если ключ вставили в файл руками и нажали
Enter, без `.strip()` сервер получит ключ с `\n` на конце и ответит 403.

### Шаг 3. Проверяем ключ

```python
key = load_key()
headers = {"X-API-Key": key}

response = requests.get(BASE_URL + "/me", headers=headers, timeout=10)
if response.status_code != 200:
    print(f"Ключ не подходит (код {response.status_code}):", explain(response))
    print(f"Удали файл {KEY_FILE} и запусти программу снова — получишь новый ключ.")
    raise SystemExit
print(response.json()["message"])
```

`/me` — «кто я». С правильным ключом сервер ответит «Ключ работает, Вася!». Словарь `headers`
мы собираем один раз и дальше передаём в каждый запрос, где нужен ключ.

`raise SystemExit` — аккуратно завершить программу: дальше без ключа всё равно ничего не выйдет.

### Шаг 4. Читаем доску

```python
def show_board():
    response = requests.get(BASE_URL + "/board", params={"limit": 10}, timeout=10)
    messages = response.json()["messages"]
    if not messages:
        print("На доске пока пусто. Напиши первым!")
    for message in messages:
        hour = message["time"][11:16]
        print(f"[{hour}] {message['author']}: {message['text']}")
```

Читать доску можно без ключа — это обычный GET. Ответ:

```json
{
  "count": 2,
  "total": 57,
  "messages": [
    {"id": 56, "author": "Вася", "text": "Всем привет!", "time": "2026-11-19T15:04:05"},
    {"id": 57, "author": "Маша", "text": "Привет с Кеплера!", "time": "2026-11-19T15:04:31"}
  ]
}
```

`total` — сколько сообщений на доске всего, `count` — сколько пришло сейчас. Сообщения идут
**от старых к новым**, как в любом чате: новое — внизу. Время — срез строки, как в уроке 5.

Параметры доски: `limit` — сколько последних сообщений (от 1 до 100), `after` — только
сообщения с `id` больше заданного (пригодится в заданиях, чтобы получать **только новые**).

### Шаг 5. Пишем на доску

```python
def send(text):
    response = requests.post(BASE_URL + "/board", json={"text": text}, headers=headers, timeout=10)
    if response.status_code == 201:
        print("Отправлено! Номер сообщения:", response.json()["id"])
    else:
        print(f"Ошибка {response.status_code}:", explain(response))
```

Здесь встретилось всё сразу: метод POST, тело `json=` и заголовок с ключом `headers=`. В ответ
сервер присылает сообщение, которое сохранил: с номером, твоим именем и временем.

Правила доски: текст от 1 до 200 символов; не чаще одного сообщения в 3 секунды. Нарушишь —
сервер ответит 400 или 429 и объяснит, что не так.

### Шаг 6. Меню

```python
while True:
    print("\n1 — показать доску, 2 — написать сообщение, 0 — выход")
    choice = input("> ").strip()
    if choice == "1":
        show_board()
    elif choice == "2":
        send(input("Сообщение: "))
    elif choice == "0":
        print("До связи!")
        break
    else:
        print("Нет такого пункта")
```

То же меню, что на уроке 3.

## Подробный разбор: `json=` и `data=`

У `requests.post` есть два похожих параметра, и их легко перепутать:

- `json={"text": "Привет"}` — отправить **JSON**: `{"text": "Привет"}`;
- `data={"text": "Привет"}` — отправить **форму**, как HTML-форма на сайте: `text=Привет`.

Наш сервер (как и большинство API) ждёт JSON. Если отправить `data=`, он ответит 400 и подскажет:
«Отправляй json={...}, а не data=...». Правило простое: **для API — `json=`**.

## Подробный разбор: почему ключ в заголовке, а не в адресе

Можно было бы передавать ключ параметром: `/board?key=kp-...`. Но адрес видно везде: в истории
браузера, в журналах серверов, на скриншоте экрана. Заголовки там обычно не показываются, поэтому
ключи и пароли передают в них.

Имя `X-API-Key` придумал наш сервер. У других API заголовок может называться иначе — например,
`Authorization: Bearer <ключ>`. Как именно передавать ключ, всегда написано в документации API.

## Подробный разбор: 429 и «подожди»

Если запросы приходят слишком часто, сервер отвечает **429 Too Many Requests**. Это защита: без
неё один скрипт с `while True` мог бы засыпать доску тысячами сообщений за минуту.

Вместе с 429 наш сервер присылает заголовок **`Retry-After`** — через сколько секунд можно
повторить:

```python
if response.status_code == 429:
    wait = int(response.headers["Retry-After"])
    time.sleep(wait)
```

Так ведут себя вежливые программы: получили 429 — подождали — попробовали снова (задание 8).

## Подробный разбор: как сервер защищает доску

Сообщения учеников показываются на проекторе страницей `/board.html`. Что будет, если кто-то
отправит `<script>alert(1)</script>`? Если бы страница вставляла сообщения как HTML, этот код
**выполнился бы** на компьютере учителя — так взламывают сайты (это называется XSS). Наша
страница вставляет сообщения как **обычный текст**, поэтому на проекторе ты увидишь просто
символы `<script>…`. Правило для всех, кто делает сайты: **данные от пользователей — только как
текст, никогда как код**.
