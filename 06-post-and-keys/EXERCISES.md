# Урок 6. Задания

Ниже — подсказки, **не готовый код**. Эталонные решения — в папке [solutions](solutions/README.md).

Каждое задание удобно делать в отдельном файле, начиная с `import requests` и
`BASE_URL = "https://api-lessons-sidorenkoai.msk1.amvera.tech"`. Почти везде нужен твой ключ:
скопируй функцию `load_key()` из `main.py` (или читай ключ из `key.txt`, который уже создал
`main.py`, — положи файл рядом с программой).

Правила доски: текст 1–200 символов, не чаще одного сообщения в 3 секунды. Доска общая — пиши
по делу, учитель видит всё.

## Лёгкие

### 1. Пропустят или нет?

Отправь запрос к `/me` три раза: **без** ключа, с **выдуманным** ключом и со **своим**. Для
каждого напечатай код ответа и текст — `message` или `error`.

```
Без ключа: 401 — Нужен ключ API: добавь заголовок X-API-Key. ...
Выдуманный ключ: 403 — Неверный ключ API: такого ключа нет. ...
Свой ключ: 200 — Ключ работает, Вася!
```

- Три попытки удобно записать списком пар `(название, заголовки)` и пройти циклом.
- Без ключа — это пустой словарь заголовков `{}`.
- Объясни своими словами: чем 401 отличается от 403?

### 2. Доска с датой и автором

Напечатай последние 20 сообщений доски в виде `19.11 15:04  Вася: текст`. Свои сообщения
отметь пометкой `(я)`. В конце — сколько среди них твоих.

- Своё имя узнай у сервера: `/me` с ключом.
- Дата `19.11` — это два среза строки `time`, соединённые точкой. Какие номера символов?
- Сколько всего сообщений на доске, а не только показанных, — в поле `total`.

### 3. Регистрация с повтором

Программа регистрирует ученика: спрашивает имя, пока сервер его не примет. Если имя занято —
пишет «Это имя уже занято», если имя неправильное — объясняет почему (берёт текст из
`details`). Ключ сохраняет в `key.txt`. Если `key.txt` уже есть — ничего не регистрирует.

- Различай ответы по `status_code`: 201, 409, 400.
- Подробности ошибки — `response.json()["details"][0]["message"]`.
- Проверь: введи имя соседа — что ответит сервер?

## Средние

### 4. Ломаем нарочно

Отправь на доску «плохие» запросы и напечатай, что ответил сервер на каждый:

1. пустой текст;
2. текст из 250 символов;
3. без ключа;
4. `data=` вместо `json=`;
5. словарь с ключом `"message"` вместо `"text"`;
6. нормальное сообщение — и сразу второе.

- Сделай функцию `show(название, response)`: печатает код и текст ошибки вместе с `details`.
- Строка из 250 букв: `"а" * 250`.
- `response.ok` — `True`, если код ответа меньше 400.
- Какой код пришёл на шестой запрос и почему?

### 5. Ключ из переменной окружения

Ключ можно хранить не в файле, а в **переменной окружения** — тогда его нет ни в коде, ни в
папке с программой. Программа ищет ключ так: сначала переменная `COSMOPORT_KEY`, потом файл
`key.txt`, потом регистрирует нового ученика. Печатает, откуда взят ключ, и проверяет его
через `/me`.

- `import os`, затем `os.environ.get("COSMOPORT_KEY")` — вернёт `None`, если переменной нет.
- Как задать переменную в PyCharm: **Run → Edit Configurations… → Environment variables**,
  строка `COSMOPORT_KEY=kp-...`.
- Ключ целиком на экран не печатай: покажи первые 6 и последние 2 символа.

### 6. Статистика доски

Возьми последние 100 сообщений и посчитай: кто сколько написал (с «полоской» из `#`), кто пишет
больше всех, самое длинное сообщение и его автора, среднюю длину сообщения.

- Подсчёт — словарь «автор → сколько», как в уроке 1.
- Самое длинное: `max(messages, key=...)` — по длине текста.
- Сортировка словаря по значению: `sorted(counts.items(), key=lambda pair: pair[1], reverse=True)`.

### 7. Следим за доской

Программа спрашивает, сколько секунд следить, и всё это время раз в 2 секунды спрашивает сервер
о **новых** сообщениях и печатает только их. В конце — сколько новых сообщений пришло.

- Сначала узнай `id` самого свежего сообщения: `/board?limit=1`.
- Потом в цикле: `/board?after=<последний id>` — сервер пришлёт только то, что новее.
  После печати запомни `id` последнего.
- Пауза: `import time`, `time.sleep(2)`. Почему не стоит спрашивать сервер 100 раз в секунду?
- Секундомер: `finish = time.monotonic() + seconds`, цикл `while time.monotonic() < finish`.
- Проверь вдвоём: один следит, другой пишет.

## Посложнее

### 8. Длинное сообщение частями

Сообщение длиннее 200 символов сервер не примет. Напиши программу, которая режет длинный текст
на части (не разрывая слова), нумерует их `(1/3) …` и отправляет по очереди. Если сервер ответил
429 — подождать столько секунд, сколько он просит в заголовке `Retry-After`, и отправить снова.

- Резать по словам: идём по `text.split()` и добавляем слово в текущий кусок, пока он не стал
  длиннее нужного.
- Номер части тоже занимает место — режь кусками поменьше, например по 190.
- Заголовок ответа: `response.headers["Retry-After"]` — это строка, переведи в число.
- `for ... else`: блок `else` у цикла выполняется, если цикл закончился без `break`.

### 9. Бот-синоптик

Напиши бота: он следит за доской и, когда кто-то пишет `!погода Нимбус`, отвечает на доске
сводкой погоды на сегодня: `@Вася, на планете Нимбус сегодня от -124.7 до -93.6 °C, бурь: 7 ч
из 24`. Если такой планеты нет — так и отвечает. Бот работает заданное число секунд.

- Основа — задание 7. Для каждого нового сообщения проверь `text.lower().startswith("!погода")`.
- Название планеты — всё, что после `!погода`: срез и `.strip()`.
- Прогноз — `/weather` из урока 5. Сводка — `min`, `max` и `sum(storms)`.
- Бот не должен отвечать **сам себе**: пропускай сообщения, где автор — бот.
- Бот тоже подчиняется правилу «одно сообщение в 3 с»: на 429 подожди и повтори.
- Придумай ещё команды: `!планета Кеплер-Б`, `!житель 17`…
