# Урок 6. Отправляем данные: POST и ключ API

## Цель

Показать, что API умеет не только **отдавать** данные, но и **принимать** их, и зачем для этого
нужен личный ключ. Ученики регистрируются на сервере (`POST /register`), получают ключ, хранят его
в файле и передают в заголовке `X-API-Key`. Итог урока — консольный клиент **доски станции**:
читать последние сообщения и отправлять свои. Доска общая, учитель выводит её на проектор — каждое
отправленное сообщение класс видит сразу.

Ключ, полученный сегодня, понадобится на уроке 7 (квест), поэтому файл `key.txt` нужно сохранить.

## Перед началом

- Пройдены уроки 3–5: ученики уверенно делают `requests.get` с `params=`, проверяют
  `status_code` и читают `["error"]` из ответа.
- Откройте без VPN на проекторе https://api-lessons-sidorenkoai.msk1.amvera.tech/board.html —
  страница обновляется сама раз в 3 секунды.
- Откройте у себя **страницу учителя** `/admin?key=<ADMIN_KEY>` (ключ задаётся переменной
  `ADMIN_KEY` на Amvera). Там видно всех зарегистрированных с их ключами, последние сообщения
  с кнопкой «удалить» и кнопки очистки. Если доска с прошлой группы не пустая — «Очистить доску».
- Договоритесь об именах: **настоящее имя или ник**, 2–20 символов, без смайликов. Имя
  занимается навсегда: зарегистрироваться второй раз под тем же именем нельзя (ответ 409).
- Сервер ограничивает частоту: не больше одного сообщения в 3 секунды от одного ученика
  (ответ 429). Если кто-то зальёт доску — это нормальный повод поговорить о том, зачем API лимиты.

## Теория (10 минут)

- **GET и POST.** До сих пор мы только спрашивали: «дай планету 2». Это GET — всё, что нужно
  серверу, помещается в адрес (`/planets/2?full=true`). Чтобы что-то **отправить** — сообщение,
  анкету, ответ квеста, — нужен метод **POST**: у запроса появляется **тело** с данными. Сравнение
  с почтой: GET — открытка, где всё написано на адресе; POST — конверт, внутри которого письмо.
- **Тело запроса** — обычно JSON. В `requests` это одна буква разницы: `requests.post(url,
  json={"text": "Привет"})` — словарь сам превратится в JSON (вспоминаем `json.dumps` из урока 2).
- **Заголовки** — служебные строки запроса «на конверте»: кто отправляет, в каком формате.
  Свой заголовок передаётся словарём: `headers={"X-API-Key": key}`. Заголовки ученики уже видели —
  `r.headers["content-type"]` на уроке 4.
- **Зачем ключ.** Читать доску может кто угодно, а писать — только «представившись». По ключу
  сервер знает, **кто** написал (подпись под сообщением), может **ограничить** частоту и, если
  что, **отключить** хулигана, не трогая остальных. Ключ — как пропуск: его не показывают и
  не отдают соседу. У настоящих API (погода, карты, нейросети) ключ привязан к оплате — утёкший
  ключ означает чужие запросы за ваши деньги.
- **Новые коды ответа** — нарисуйте табличку на доске:

  | Код | Значит | Когда у нас |
  |---|---|---|
  | 201 | Created — создано | регистрация, новое сообщение |
  | 400 | неверные данные | пустой текст, слишком длинное имя, `data=` вместо `json=` |
  | 401 | не представился | нет заголовка `X-API-Key` |
  | 403 | представился, но не пускаем | ключ неверный |
  | 409 | конфликт | имя уже занято |
  | 429 | слишком часто | два сообщения быстрее чем за 3 с |

  Многие API на неверные данные отвечают 422 — наш сервер для простоты всегда отвечает 400.

## Пошаговый план занятия

1. **Регистрация в браузере.** Откройте `/docs`, раздел «Ключи», `POST /register` →
   **Try it out**. В поле тела — JSON `{"name": "Учитель"}` → **Execute**. Покажите: метод POST,
   тело запроса, код **201**, в ответе — `api_key`. Нажмите ещё раз — **409**, имя занято.
   Ученики в браузере **не** регистрируются: сделаем это кодом.

2. **Регистрация кодом.** Функция `register()`: `requests.post(BASE_URL + "/register",
   json={"name": name}, timeout=10)`, проверка `status_code == 201`, цикл `while True`, пока
   имя не примут. Пусть кто-нибудь нарочно введёт одну букву — сервер ответит 400 и объяснит
   почему. Функция `explain()` собирает текст ошибки вместе с `details`.

3. **Ключ — в файл.** `load_key()`: открыть `key.txt`; если файла нет (`FileNotFoundError`, урок 2)
   — зарегистрироваться и записать ключ. Запустите программу **два раза**: во второй раз имя уже
   не спрашивают. Откройте `key.txt` в PyCharm — внутри одна строка `kp-...`.

4. **Проверка ключа: `/me`.** `requests.get(BASE_URL + "/me", headers=headers)` → «Ключ работает,
   Вася!». Попробуйте без `headers=` — **401**; испортите одну букву ключа — **403**. Обсудите,
   чем 401 отличается от 403.

5. **Читаем доску.** `GET /board?limit=10` — ключ не нужен. В ответе `messages` — список словарей
   (`id`, `author`, `text`, `time`), старые сверху. Время режем срезом `[11:16]`, как в уроке 5.

6. **Пишем на доску.** `send(text)`: `requests.post(BASE_URL + "/board", json={"text": text},
   headers=headers)`. Код 201 — смотрим на проектор: сообщение появилось с подписью автора.
   Попросите отправить два сообщения подряд очень быстро — увидят **429**.

7. **Меню** — цикл `while True` с пунктами 1/2/0, как в уроке 3. Готово.

8. **Безопасность — 3 минуты.** Попросите кого-нибудь отправить `<b>жирный</b>` или
   `<script>alert(1)</script>`. На проекторе это **просто текст**: страница вставляет сообщения как
   текст, а не как HTML. Если бы вставляла как HTML — любой ученик мог бы запустить свой код на
   компьютере учителя. Это называется XSS, и это одна из самых частых дыр на сайтах.

## Контрольная точка

`main.py` при первом запуске регистрирует ученика и сохраняет ключ в `key.txt`, при следующих —
сразу пишет «Ключ работает, <имя>!». Пункт 1 показывает последние сообщения со временем и
автором, пункт 2 отправляет сообщение, и оно появляется на проекторе. Ошибки (пустое сообщение,
429) не роняют программу, а печатаются понятным текстом.

**Напомните сохранить `key.txt`** — на уроке 7 он понадобится в папке квеста.

## Частые проблемы

- **400 «тело запроса должно быть объектом JSON… а не data=»** — написали `data={...}` вместо
  `json={...}`. `data=` отправляет форму (как HTML-форма на сайте), а сервер ждёт JSON.
- **400 «text: обязательный параметр»** — в словаре не тот ключ: `{"message": ...}` вместо
  `{"text": ...}`. Какие поля нужны — в `/docs`, раздел «Schema».
- **401** — забыли `headers=headers` в вызове. Частая ошибка: заголовки передали в `requests.get`
  для `/me`, а в `requests.post` для доски — забыли.
- **403** — в ключе лишний пробел или перенос строки (читайте файл с `.strip()`), ключ скопирован
  не целиком, или учитель удалил игроков в `/admin`. Лечение — удалить `key.txt` и запустить
  программу снова.
- **409 «имя уже занято»** — ученик удалил `key.txt` и регистрируется заново под тем же именем.
  Ключ можно найти на странице учителя и вписать в `key.txt` вручную.
- **`key.txt` не находится** или создаётся «не там» — программа запущена не из своей папки.
  В PyCharm файл появляется рядом со скриптом, если в Run Configuration рабочая папка
  (Working directory) — папка скрипта (так по умолчанию).
- **Сообщение ушло, но на проекторе его нет** — страница обновляется раз в 3 секунды, подождите.
  Если всё равно нет — проверьте код ответа: 201 значит, сообщение точно на сервере.
- **`KeyError: 'messages'`** — в ответе ошибка, а не доска: печатайте `response.json()` целиком.

## Дополнительно

- **Почему ключ в заголовке, а не в адресе?** Адрес (`?key=...`) сохраняется в истории браузера и
  в журналах серверов — его легко «засветить». Заголовки там обычно не видны. Многие настоящие API
  всё равно принимают ключ в адресе (например, OpenWeatherMap — `appid=`), но заголовок надёжнее.
- **Другие методы.** Кроме GET и POST бывают PUT/PATCH (изменить) и DELETE (удалить). Вместе их
  называют CRUD: create, read, update, delete. На нашем сервере удалять сообщения может только
  учитель.
- **Swagger с ключом.** В `/docs` есть кнопка **Authorize**: вставьте туда ключ — и все запросы
  из браузера пойдут с заголовком `X-API-Key`. Удобно показать, что `POST /board` работает и без
  Python.
- **Опрос сервера («polling»)** — задание 7 и бот из задания 9 раз в несколько секунд спрашивают
  «есть новенькое?». Так работают простые чат-боты. Настоящие чаты используют постоянное
  соединение (WebSocket), где сервер сам присылает новое, — это тема отдельного курса.
